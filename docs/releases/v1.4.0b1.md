# Ayikla 1.4.0b1 · local beta candidate

- Portable shoot bookmarks include round, filename and capture time. Missing
  files fall back to the nearest undecided capture; Start from first changes
  navigation only. Summary screens retain the last photo bookmark.
- Round 1 progress adds a session median pace estimate after ten decisions.
- Ctrl+I imports recursive card folders with size/SHA-256 verification,
  identical-copy skipping, cancel and durable batch undo. The card is read only.
- Round 2 summary exports a contact sheet as JPEG with an optional PDF of the
  same grid. Repeat exports get numbered names and can be undone together.

The main journal keeps reading older records and extends view records with
`resume`. It adds `import` and `contact_sheet` actions and `imported` verification
receipts. `ayikla_import.jsonl` journals staging, verification, publication,
partial-file cleanup and skip decisions. A published import interrupted before
main-journal adoption is recovered on reopen. Undo archives verified copies;
it never writes back to the card. Only incomplete private `.part` files are
deleted during cleanup. Keep both journals and `.ayikla_saklanan`.

After using new 1.4 operations, keep using 1.4 or later; older apps reject unknown
operations. Import logs contain local source paths and should not be shared.

Card folder structures are flattened, so conflicting filenames need separate
shoots or manual naming outside Ayikla. No physical SD-card removal or power
loss is claimed by generated-file interruption tests. Contact sheets use a
single raster grid (also inside PDF), capped at 80 MP / 65,000 pixels in height.
Large TIFF source decoding retains the 1.3 memory limitation.

This version is built locally. Tagging, pushing and publishing remain separate
actions requiring Emir's approval.
